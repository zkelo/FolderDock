Папки на панели задач Windows 11 — как в Dock на macOS. Клик по закреплённому значку папки → всплывающее окно с содержимым (сетка или список) прямо над панелью задач, без Проводника.

Проект целиком и полностью поддерживается нейросетями **Claude Fable 5** и **GPT 6.1 Sol**.

## Возможности

- **Закрепление любой папки** на панели задач через ярлык с собственным AppUserModelID — каждая папка получает отдельную кнопку, они не группируются между собой.
- **Popup над панелью задач**: сетка с миниатюрами (изображения — превью) или компактный список. Переключение кнопкой в заголовке.
- **Рекурсивный поиск** в сетке и списке: непустой запрос ищет файлы и папки по части имени без учёта регистра в текущей папке и её подпапках, в фоновом режиме после короткой паузы при вводе. Относительные пути видны в списке и подсказках элементов сетки и списка; результаты ограничены первыми 500 совпадениями. Скрытые элементы и недоступные подпапки пропускаются; ссылки на папки и точки соединения (junction) могут попасть в результаты, но поиск по ним не переходит. Попап сообщает о неполном поиске и достижении лимита. Очистка запроса возвращает содержимое текущей папки. **Ctrl+F** переводит фокус в строку поиска; запрос очищается при переходе в другую папку и повторном открытии попапа. Изменение запроса, переход или скрытие попапа отменяют предыдущий поиск.
- **Адаптивное поле поиска**: поиск расположен в строке с названием папки, если полное название и кнопки заголовка помещаются; иначе поле переносится в отдельную строку ниже.
- Клик по файлу → открытие приложением по умолчанию с передачей **контекста папки** (`NeighboringFilesQuery`), чтобы поддерживающие его просмотрщики могли листать соседние файлы. Для «Фото» Windows используется URI просмотрщика, если это приложение выбрано по умолчанию. При неудаче выполняется обычный запуск через оболочку Windows. Popup закрывается, если не закреплён.
- Клик по подпапке → навигация внутрь прямо в popup; кнопка **«Назад»** возвращает к предыдущей папке в истории переходов.
- **Типизированный drag-and-drop**: пакет данных содержит несколько представлений — одно изображение поддерживаемого формата дополнительно предлагается как Bitmap (вставка «как картинка» в совместимые приложения), один поддерживаемый текстовый файл размером до 256 КиБ — как Text, а файлы и папки — как StorageItems. Приложение-приёмник само выбирает формат, который понимает. По умолчанию запрашивается **перемещение**, с зажатым **Ctrl** — копирование. Итоговую операцию определяет приёмник. После перемещения содержимое попапа обновляется автоматически.
- **Контекстное меню Проводника** (ПКМ по элементу): настоящее системное меню шелла — «Открыть с помощью», «Отправить», Копировать/Вырезать/Удалить/Переименовать, сторонние расширения (7-Zip, TortoiseGit, …) — ровно как в Проводнике. То же меню доступно на строках менеджера: ПКМ по закреплённой папке → **«Закрепить на панели задач»**, переименовать или удалить ярлык — без перехода в Проводник.
- Кнопка «Открыть в Проводнике».
- **Закрепление попапа** кнопкой в заголовке оставляет его открытым поверх окон при клике снаружи, открытии файлов и выборе «Открыть в Проводнике». Закрепление сохраняется при навигации и переключении сетки/списка, но сбрасывается при каждом новом открытии попапа, в том числе для другой папки.
- Клик мимо незакреплённого окна → popup закрывается (поведение флайаута).
- Кнопка **«Закрыть»** в заголовке или повторный клик по значку на панели задач закрывают попап, даже если он закреплён. **Esc** сначала очищает непустой поиск, а при пустом поиске закрывает попап.
- Менеджер показывает только «живые» закрепления: ярлыки, чья целевая папка удалена, отфильтровываются при каждой активации окна.
- **Обновления из GitHub Releases**: кнопка «Проверить обновления» и тумблер автопроверки (хранится в `%LOCALAPPDATA%\FolderDock\settings.json`). Автопроверка включена по умолчанию и выполняется при создании окна менеджера. При выходе новой версии приложение предлагает скачать установщик под архитектуру работающего приложения и после подтверждения запускает тихое обновление.
- Запуск с ярлыка самого приложения (меню Пуск) сохраняет собственную идентичность на панели задач — программа не «притворяется» одной из закреплённых папок.
- **Нативный акрил Windows** в менеджере и попапе папки: скруглённые поверхности содержимого и полупрозрачные края. Размытые оттенки берутся с рабочего стола и окон за FolderDock, поэтому вид переливов зависит от фона.
- **Системные акцент и тема**: элементы управления и подсветка следуют акцентному цвету Windows и светлой/тёмной теме. При отключённой прозрачности, включённой контрастной теме или недоступности акрила Windows использует соответствующий непрозрачный фон.
- Скруглённые углы попапа Win11, поверх окон, нет в Alt-Tab.
- **Быстрое первое открытие после входа в Windows**: при первом обычном запуске приложение включает фоновый запуск для текущего пользователя. При входе оно заранее создаёт скрытое окно папки, без менеджера и без чтения содержимого папок. Настройку «Запускать в фоне при входе в Windows» можно отключить в менеджере; Windows также может отдельно запретить автозапуск. Закрытие менеджера оставляет подготовленный процесс в фоне.
- **Отзывчивое открытие папок**: окно показывает состояние загрузки сразу, чтение каталога выполняется в фоне за один проход, а миниатюры запускаются после кадра с именами файлов.
- Single-instance: повторные запуски перенаправляются работающему экземпляру (AppInstance redirect).

## Установка

Скачай `FolderDock-Setup-<версия>-<арх>.exe` из [Releases](https://github.com/zkelo/FolderDock/releases) и запусти. Установщик позволяет выбрать папку установки, опционально создаёт группу в меню «Пуск» и тихо удаляет ранее установленную версию перед обновлением.

Доступны установщики для **x64** и **ARM64**. К выпускам прикладываются только `FolderDock-Setup-<версия>-x64.exe` и `FolderDock-Setup-<версия>-arm64.exe`; переносимые архивы приложения не публикуются.

## Сборка (на Windows)

Требования:
- Windows 10 17763+ / Windows 11
- [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)
- Visual Studio 2022 с workload **Windows application development** необязательна; команды ниже используют SDK напрямую

Командная строка:

```powershell
cd FolderDock
dotnet build FolderDock.csproj -c Release -r win-x64 -p:Platform=x64
# или сразу готовый exe (self-contained, WindowsAppSDKSelfContained — MSIX не нужен):
dotnet publish FolderDock.csproj -c Release -r win-x64 -p:Platform=x64
# ARM64:
dotnet publish FolderDock.csproj -c Release -r win-arm64 -p:Platform=ARM64
```

Результат: `bin\x64\Release\net8.0-windows10.0.19041.0\win-x64\publish\FolderDock.exe` (ARM64: `bin\ARM64\Release\net8.0-windows10.0.19041.0\win-arm64\publish\FolderDock.exe`). Сохраняй всё содержимое папки publish вместе с исполняемым файлом.

> WinUI 3 не собирается на Linux/macOS (XamlCompiler.exe — только Windows). Собирать на Windows.

## Тесты

Тесты Core проверяют сессию попапа, состояние навигации и поиска, отменённые и устаревшие запросы, правила автозапуска, поведение при сбоях настроек, доступные ярлыки, выбор обновления и границы зависимостей. Тесты инфраструктуры проверяют разбор запуска, очередь активаций, чтение каталогов, рекурсивный поиск, совместимость JSON-настроек, разбор ответов GitHub, ошибки и отмену скачивания установщика. Ответы HTTP и запуск установщика имитируются; проверки файловой системы используют временные каталоги. Им нужен только .NET 8 SDK; они работают на Windows, Linux и macOS:

```sh
dotnet test tests/FolderDock.Core.Tests/FolderDock.Core.Tests.csproj -c Release
dotnet test tests/FolderDock.Infrastructure.Tests/FolderDock.Infrastructure.Tests.csproj -c Release
```

Тесты Core ссылаются только на `FolderDock.Core`, тесты инфраструктуры — на `FolderDock.Infrastructure`. Архитектурные тесты проверяют скомпилированные зависимости и запрещают внутри Core обращения к файловой системе, реестру, сети, процессам, сериализации и нативным API/COM. Они также запрещают обратные зависимости инфраструктуры от интерфейса. [CI](.github/workflows/tests.yml) запускает тесты на Ubuntu и Windows, публикует приложение WinUI с ReadyToRun для x64 и ARM64 на Windows и сохраняет переносимые сборки на 14 дней.

## Использование

1. Запусти `FolderDock.exe` без аргументов → окно-менеджер.
2. «Добавить папку» → выбери папку → создаётся ярлык в `%LOCALAPPDATA%\FolderDock\Shortcuts`.
3. ПКМ по папке в списке → **«Закрепить на панели задач»** (настоящее меню Проводника — закрепление, переименование, удаление, свойства без выхода из менеджера).
4. Клик по закреплённому значку → popup с содержимым папки.

Так можно закрепить сколько угодно папок — у каждой свой значок.

## Локализация

Языки интерфейса: **English (en-US, по умолчанию)**, **Русский (ru)**, **Українська (uk)**. Язык выбирается по списку предпочитаемых языков Windows; отсутствующие строки откатываются к английскому.

Все строки — в одном файле на язык: `Strings/<тег BCP-47>/Resources.resw`. Чтобы добавить язык:

1. Скопируй `Strings/en-US/` в `Strings/<твой тег>/` (например, `Strings/de-DE/`).
2. Переведи элементы `<value>` — ключи должны совпадать во всех языках.
3. Пересобери. Всё — без правок кода: WinUI PRI подхватывает папку автоматически.

Соглашения о ключах: ключи с точкой (`AddFolderLabel.Text`) привязываются к XAML-элементам через `x:Uid`; простые ключи (`Update_Checking`) используются из кода через `Loc.Get`/`Loc.Format` (`{0}`, `{1}` — подстановки, сохраняй их в переводах).

## Как это работает

- Windows 11 не даёт закрепить папку на панель задач напрямую и не имеет API для popup «из панели». Обход: ярлык на `FolderDock.exe --folder "<путь>"` с записанным в property store ярлыка `System.AppUserModel.ID`, уникальным для каждой папки (SHA1 от пути). Процесс при старте ставит себе тот же AUMID через `SetCurrentProcessExplicitAppUserModelID` — панель задач сопоставляет окно с нужным закреплённым значком. При запуске без `--folder` процесс (и каждое окно через `SHGetPropertyStoreForWindow`) использует собственный AUMID приложения.
- Один фоновый процесс: `AppInstance.FindOrRegisterForKey` + `RedirectActivationToAsync`. Входящие активации сохраняются, пока интерфейс ещё запускается. Фоновый запуск использует `--background` и запись текущего пользователя `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`; повторный фоновый запуск не открывает менеджер и не переключает уже открытый попап.
- Подготовленный процесс принимает клики по ярлыкам без повторной инициализации WinUI. Windows может задерживать запуск программ при входе, поэтому клик до завершения подготовки всё ещё потребует холодного запуска. Release-публикация использует ReadyToRun для снижения затрат JIT; точное время открытия зависит от компьютера и требует замера на Windows.
- Первое обычное открытие после установки или обновления настраивает автозапуск; сохранённое отключение и запрет Windows не отменяются. При переносе переносимой версии существующая запись обновляется на новый путь. При удалении установленной версии удаляется её запись автозапуска для пользователя, от имени которого работает деинсталлятор. Перед удалением переносимой копии или удалением от имени другого администратора отключите настройку в менеджере исходного пользователя.
- Popup — WinUI 3 `Window` c `OverlappedPresenter.CreateForContextMenu()` (без рамки), `IsAlwaysOnTop`, `WS_EX_TOOLWINDOW` (нет в Alt-Tab), `DWMWA_WINDOW_CORNER_PREFERENCE=ROUND`. Положение по горизонтали привязано к курсору в момент открытия и ограничено рабочей областью выбранного монитора; нижний край окна расположен над нижней границей рабочей области с зазором для панели задач. При навигации точка привязки сохраняется.
- Оба окна используют `Window.SystemBackdrop` с `DesktopAcrylicBackdrop`: размытием, реакцией на активацию и заменой материала управляет Windows. Кисти WinUI `ThemeResource` предоставляют текущие системные цвета акцента и темы без отдельной настройки цвета в приложении.
- Миниатюры — `StorageFile.GetThumbnailAsync` (те же превью, что в Проводнике), грузятся асинхронно после показа окна.

## Архитектура

`FolderDock.Core` содержит правила приложения и необходимые для их выполнения интерфейсы. Это закрепление и закрытие попапа, состояние навигации и поиска, отмена запросов и отклонение устаревших результатов, правила автозапуска, поведение при сбоях настроек, фильтрация недоступных целей ярлыков и выбор обновления для текущей версии и архитектуры. Общий `LatestRequestSession` управляет запросами загрузки папок и поиска. При ошибке сохранения настройки продолжают действовать в текущем сеансе; результаты проверки обновлений содержат данные и категории ошибок, а не текст интерфейса.

`FolderDock.Infrastructure` реализует адаптеры файловой системы, реестра, JSON-настроек, получения выпусков по HTTP и установки обновлений. Здесь также находятся разбор аргументов и очередь перенаправленных активаций. Адаптеры чтения выполняют блокирующую работу с диском в фоновых задачах, а настройки сохраняются с атомарной заменой JSON-файла. Работа с ярлыками оболочки Windows и адаптеры WinUI остаются в проекте приложения. `App` собирает зависимости и передаёт их окнам через конструкторы; окна преобразуют ввод, отображают результаты, локализуют ошибки и управляют показом, включая момент загрузки миниатюр.

Направление зависимостей: **WinUI → Core**, **WinUI → Infrastructure → Core**. Ядро не зависит от внешних слоёв и адаптеров операционной системы, сети или хранения данных. Ответственность компонентов, правила зависимостей и порядок проверки описаны в [руководстве по архитектуре](docs/architecture.md).

## Ограничения

- Закрепление на панель — вручную через ПКМ (программный pin Windows не разрешает сторонним приложениям).
- Первый запуск создаёт процесс приложения; последующие клики перенаправляются в этот экземпляр, пока он работает. Время запуска зависит от системы.
- Просмотр папки и рекурсивный поиск показывают не более 500 элементов. Поиск проверяет имена, а не содержимое файлов или полный относительный путь.
- Иконка ярлыка — стандартная папка из imageres; можно сменить в свойствах ярлыка.

## Политика подписи кода (Code signing policy)

При включённой подписи бесплатную подпись кода предоставляет [SignPath.io](https://about.signpath.io), сертификат — [SignPath Foundation](https://signpath.org). Шаги подписи в [релизном workflow](.github/workflows/release.yml) выполняются, только если настроен секрет организации SignPath; иначе workflow публикует неподписанные артефакты.

Релизные бинарники (`FolderDock.exe` и установщики) собираются из этого репозитория в GitHub Actions; шаги подписи отправляют эти артефакты CI в SignPath и ожидают завершения. Для доступа к сервису используются секреты репозитория; закрытый ключ подписи в репозитории не хранится.

Права на репозиторий и одобрение подписи:

- Авторы (право коммита): [zkelo](https://github.com/zkelo)
- Ревьюеры: [zkelo](https://github.com/zkelo) — все внешние pull request'ы проходят ревью мейнтейнера до слияния.
- Утверждающие: [zkelo](https://github.com/zkelo) — каждый запрос на подпись требует явного одобрения мейнтейнера.

### Политика конфиденциальности

В приложении нет кода телеметрии. Проверка обновлений обращается к GitHub API (`api.github.com`) за сведениями о релизе и передаёт версию приложения в заголовке User-Agent. Автопроверка включена по умолчанию при открытии менеджера; её можно отключить в настройках приложения (`autoCheckUpdates`), сохранив ручную проверку. После подтверждения обновления скачивается установщик выбранного релиза. Ссылка на репозиторий открывается в браузере по умолчанию. Доступ к выбранной сетевой папке выполняется обычными файловыми операциями Windows.
